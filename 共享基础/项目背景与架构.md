## 一、项目背景

随着电商、金融、物流、生活服务等消费场景的爆发式增长，消费者维权投诉呈现**量大、渠道分散、人工处理效率低**的态势：

- **投诉渠道分散**：黑猫投诉、12315、各电商平台站内投诉、政务热线等，同一问题可能被重复提交到多个渠道；
- **人工分派效率低**：平台和监管机构需要人工阅读投诉内容、判断所属领域、再转办给对应部门，耗时且容易错分；
- **响应不及时**：同类投诉（如"快递丢件""预付费跑路"）无法被快速聚类和识别，影响维权时效。

本项目希望用 **AI 文本分类技术**构建一个"**AI 消费维权助手**"：用户输入投诉内容，系统自动完成
**领域分类 → 转办部门建议 →（扩展）处理优先级**，帮助平台与监管机构提升投诉分派效率，帮助消费者更快获得回应。

## 二、项目目标

### 功能目标
在 Web 页面输入投诉内容后，模型输出：
1. **投诉所属领域**（8~15 类，如：电商、金融支付、物流快递、生活服务、数码3C、旅游出行、教育、房产家装、医疗健康、汽车、餐饮食品等）；
2. **建议转办部门**（如：市场监管部门、金融监管部门、平台客服、消协等）；
3. （可选扩展）**处理优先级**：紧急/一般/建议优先处理。

### 技术目标
- 多分类模型在测试集上 **准确率 ≥ 90%、F1 ≥ 0.88**（基线起步，逐步提升）；
- 完成 **模型压缩优化**（剪枝/蒸馏/量化），使模型可在低配环境部署；
- 部署为 **Web 服务**，前端可交互演示（答辩现场可操作）。

## 四、项目技术架构（仿"投满分"流程）

```
┌──────────┐   ┌──────────┐   ┌──────────┐   ┌──────────┐   ┌──────────┐
│ 数据获取  │ → │ 数据预处理 │ → │  EDA     │ → │ 特征工程  │ → │ 模型训练  │
│ (爬虫)   │   │ 缺失/异常/ │   │ 词云/分布/ │   │ TF-IDF/   │   │ 基线→进阶 │
│          │   │ 重复/清洗  │   │ PCA降维   │   │ 词向量    │   │          │
└──────────┘   └──────────┘   └──────────┘   └──────────┘   └─────┬────┘
                                                                  ↓
┌──────────┐   ┌──────────┐   ┌──────────┐   ┌──────────┐   ┌──────────┐
│ Web前端   │ ← │ 模型部署  │ ← │ 模型优化  │ ← │ 模型评估  │ ← │ 训练完成  │
│ 输入投诉   │   │ Flask/    │   │ 剪枝/蒸馏/ │   │ acc/F1/   │   │          │
│ →分类→转办│   │ FastAPI   │   │ 量化      │   │ 混淆矩阵  │   │          │
└──────────┘   └──────────┘   └──────────┘   └──────────┘   └──────────┘
```

各环节要点：
1. **数据获取**：编写爬虫抓取黑猫投诉"投诉详情页"（标题、正文、所属领域），限速+随机UA防封；
2. **数据预处理**：缺失值、异常值、重复值处理；去除HTML/广告噪声；统一编码（UTF-8）；**分层采样**切分训练/验证/测试集，保证各类别比例一致；
3. **EDA**：类别分布直方图、投诉文本长度分布、词云、TF-IDF Top词、PCA/t-SNE 降维可视化；
4. **特征工程**：中文分词（jieba）、停用词表、TF-IDF / 词向量 / BERT tokenizer、标签编码；
5. **模型训练**：基线 → 进阶 → 优化（见下）；
6. **模型评估**：准确率、精确率、召回率、F1、混淆矩阵、多模型横向对比；
7. **模型优化**：剪枝、蒸馏、量化（创新点，参考投满分：BERT→BiGRU蒸馏、INT8量化）；
8. **模型部署**：Flask/FastAPI 封装接口 + Web 前端页面。

## 五、模型方案

| 阶段 | 模型 | 说明 | 预期指标 |
|---|---|---|---|
| 基线 | TF-IDF + 随机森林 | 快速出全套指标，验证流程 | acc ≥ 85% |
| 进阶1 | FastText（词/字符级） | 训练快，效果好 | acc ≥ 88% |
| 进阶2 | BERT（bert-base-chinese）微调 | 最优模型，含 config/dataloader/model/trainer 模块 | acc ≥ 90% |
| 展望 | GLM-4-Plus / DeepSeek zero-shot | 冷门类目兜底，体现创新 | 答辩加分项 |
| 优化 | 剪枝(L1非结构化30%) / 蒸馏(BERT→BiGRU) / 量化(动态INT8) | 模型体积↓、推理加速，给出前后指标对比 | 答辩加分项 |

## 六、部署与前端方案

- **后端**：Flask/FastAPI 加载训练好的模型，提供 `/predict` 接口；
- **前端**：单页应用——输入投诉内容 → 展示"所属领域 + 建议转办部门 + 置信度"；
- **加分展示**：投诉类别热度排行、类别分布统计图（对接 EDA 产出）。
