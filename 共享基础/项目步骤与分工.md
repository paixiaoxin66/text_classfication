# AI消费维权助手 — 项目步骤与小组分工总览

> 目标：用真实黑猫投诉数据，构建**18 类投诉自动分类系统**（传统机器学习基线 + BERT 深度学习对比），
> 最终以可演示形式交付并答辩。
> 当前进度：**数据阶段全部完成**（9043 条真实 → 30000 条训练集），剩余：模型训练、部署演示、答辩材料。

## 一、总体技术路线

```
数据采集 → 清洗/脱敏 → 分层划分 → 类别平衡+增强 → 基线模型(TF-IDF+NB/LR)
         → BERT微调 → (进阶: FastText/蒸馏/量化) → 部署演示 → 答辩
   [已完成 ✓]                                    [待完成]
```

核心逻辑：**用真实数据保证可信度，用增强解决类别失衡，用"增强前 vs 增强后"对比实验证明增强有效**（答辩主线）。

## 二、完整步骤拆解（8 个阶段）

### 阶段 0：数据采集 【已完成 ✓】
- 任务：黑猫投诉 API 爬虫（签名算法），抓取真实投诉
- 产出：`data/raw/hemao_complaints.csv`（9043 条，12 字段）
- 关键字段：category(领域) / title / summary / cotitle(投诉对象) / appeal(诉求) / issue(问题类型) / url

### 阶段 1：数据清洗与质量分析 【已完成 ✓】
- 任务：脱敏（手机号→`[PHONE]`、身份证→`[ID]`、URL→`[URL]`、订单号→`[ORDER_ID]`）、去重（精确+近似）、异常值处理
- 产出：`cleaned_complaints.csv`（8942 条）、`data_quality_report.md`（14 节体检）、`duplicate_report.csv`
- 关键决策：其他/未分类 325 条剔除（混合行业噪声），44→教育、22→服饰鞋包 数字ID映射

### 阶段 2：分层划分 【已完成 ✓】
- 任务：按类别分层抽样 80/10/10，seed 42
- 产出：Train 6886 / Val 854 / Test 877（18 类，每类严格 80/10/10）
- 关键决策：**先划分后增强** → Val/Test 100% 真实，杜绝评估泄漏

### 阶段 3：类别平衡与数据增强 【已完成 ✓】
- 任务：规则增强（领域同义词替换/诉求重排/副词插入/句子交换）+ 质量过滤（相似度/数字保持/品牌保持）
- 产出：`train_augmented.csv`（**30000** = 6886 真实 + 23114 增强）、`train_augmented_full.csv`（全字段版）
- 关键数据：母婴食品 54→416（少数类放大）、完全重复 0、泄漏 0、中位相似度 0.70
- 已知问题：88 条 summary 被平台截断（1.0%），补全工具已备（`fetch_full_text.py`，联网可跑）
- 可复现：seed 42 + 确定性哈希，同命令多次运行结果一致

### 阶段 4：基线模型（传统机器学习）【待完成 — 本轮核心】
- 任务：TF-IDF（1-2 gram）+ 朴素贝叶斯 / 逻辑回归，验证集选优
- 命令：`uv sync && uv run python train_baseline.py`
- 产出：`data/out/baseline_report.txt`（准确率/macro-F1/每类P/R）、混淆矩阵、`label_map.json`、模型 joblib
- **必做对比实验**：用 `train_real.csv`（6886 真实）训练一份 vs 用 `train_augmented.csv`（30000）训练一份 → 对比 macro-F1 提升（答辩核心论据）

### 阶段 5：BERT 微调 【待完成】
- 任务：bert-base-chinese 微调 18 类分类（自动检测 GPU/CPU）
- 命令：`uv run python train_bert.py --epochs 3`
- 产出：`data/out/bert_model/`、`bert_report.txt`、混淆矩阵
- 对比：BERT vs 基线 macro-F1（预期 BERT 高 3~8 个点）
- 注意：首次运行下载 ~400MB 模型需联网；CPU 训练约 2~4 小时

### 阶段 6：进阶优化（可选，时间够就做）【待完成】
- FastText：训练快，可做"轻量模型"对比（答辩加分项）
- 模型蒸馏/量化：BERT → 小模型（部署用，演示更流畅）

### 阶段 7：部署与现场演示 【待完成】
- 任务：把训练好的模型封装成简单接口/Web 页面：输入投诉文本 → 输出类别 + 置信度 Top3
- 技术：Flask/FastAPI 或 Streamlit（一行命令起服务）
- 产出：演示 demo（答辩现场投屏演示 3~5 条真实投诉分类）
- 注意：先本地跑通，演示当天提前 30 分钟预热

### 阶段 8：文档与答辩 【待完成】
- 已有材料：`data/reports/augmentation_report.md`、`data_quality_report.md`、`scripts/README.md`（6 条设计决策）

## 五、答辩必讲要点与风险

**必讲**（都是我们的亮点）：
1. 真实数据 + 脱敏合规（不公开传播，已做替换）
2. 只增强 Train，Val/Test 100% 真实 → 评估可信
3. 增强"有效性验证"：增强前后 macro-F1 提升数据
4. 可复现：seed 42 + 确定性哈希（两次运行结果一致）
5. 质量>数量：过滤率 74%、相似度控制、数字/品牌保持

**风险预案**：
- 电脑无 GPU：BERT 用 CPU 小轮次（--epochs 2 --batch-size 8），或改用 FastText/基线兜底演示
- 网络问题：模型下载失败 → 提前一天下载好缓存
- 答辩提问"数据怎么来的"：讲 API 签名爬虫 + 五步法（找URL规律→发请求→提字段→存CSV→翻页）
- 提问"增强会不会改变语义"：讲三层数字防护 + 品牌保持过滤 + 相似度阈值
